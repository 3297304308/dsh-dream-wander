# dsh-dream-wander

Mind-wandering and dreaming for DeepSeek Harness (DSH) agents.

- **Wandering**: when the agent is alone, the character produces a short reverie (≤50 chars). The character remembers it; it may or may not bring it up later.
- **Dreaming**: after a silence long enough to confirm sleep (`judge.confirmH`, default 1 hour), a dream is judged by a Laplacian curve over the judging window (`judge.windowH`, default 6 hours; the chance of a dream when sleeping through the whole window is `judge.hitP`, default 0.5). On a hit the dream plays out in half-acts generated by direct LLM calls, then leaves a waking residue (default: pixelated dream text) and a vague mood.
- Two independent switches: dream / wander.

> This plugin is Chinese-first. The settings UI is currently Chinese; this English file is a complete translation of `README.md`.

## Quick start (4 steps)

> ⚠️ **Both switches default to OFF and the scope is empty** — installing without enabling does nothing visible.

0. **Enable + refresh**: Settings → Plugins, make sure 「走神与做梦」 is enabled (refresh the page after install/update so the panel reloads).
1. **Install**: add the plugin directory via the Plugins page, or run `plugin_manager install_bundle` against this directory (local-directory install, see *Install*).
2. **Turn on**: Settings → 走神与做梦 → enable both switches, pick the session under *scope* — **then click Save at the bottom** (the panel is a draft: changes do not apply until saved).
3. **Verify (wander first, then dream)**:
   - Chat with the character 3–5 times so the word pool is non-empty (the panel shows the pool size; an empty pool means no dreams).
   - **Wander**: keep `confirmH` at default **1 hour**, set *alone trigger* to **10 minutes** (the smallest panel step), *wander probability* to **1.0**, save, then stay quiet for 10–11 minutes → check `<data dir>/走神/<date>.md` (default on Windows: `%USERPROFILE%\.dsh\dream-wander-data\`). Note: the default allowed window starts at 08:00, so it will not trigger between 00:00 and 08:00.
   - **Dream** (slower, optional): lower `confirmH` to **0.1 h**, judging window to **1 hour**, hit rate to **1.0**, and after the character falls asleep the hit moment is sampled randomly (on average around half the window) — the dream body never enters the chat; check `<data dir>/梦境副本/` after it ends. Set *max dream duration* to 10 minutes if you want it to finish faster.
   - Restore defaults: `confirmH` 1 h, window 6 h, hit 0.5, alone 15 min, wander chance 0.3, max duration 90 min.

**If nothing happens, check 4 things**: ① plugin enabled + page refreshed; ② both switches on + scope selected; ③ the Run Status card for errors; ④ the tail of `<data dir>/plugin.log`.

## Requirements

- **DSH 0.2.2-rc.3** (cordis 4.x) — implemented against this version's contracts; `engines.dsh` declares the compatible range and DSH refuses to load incompatible versions.
- **npm dependency**: `@deepseek-ai/schemastery` — installed automatically when installing from the npm registry; **local-directory / git-clone installs do not install the plugin's own dependencies**, so run `pnpm install` (or `npm install`) inside this directory first.
- **LLM channel**: defaults to `deepseek-account` / `deepseek-flash`; needs a logged-in DSH account.
- **Optional: qq-bridge** (external program, not bundled, not modified) — used for the signal channel (external interruption during dreams, passive reply sending, dive detection). Without it, wandering, dream judging, generation, residue/frame/mood injection and copies all work; only interruption / passive replies / dive detection are unavailable.

## Install

**npm install (recommended)**: in the DSH Plugins page add the package name `dsh-dream-wander`, or `plugin_manager install_bundle` with target `dsh-dream-wander` (published: https://www.npmjs.com/package/dsh-dream-wander; source: https://github.com/3297304308/dsh-dream-wander). Confirm it is enabled in Settings → Plugins, refresh the page, then 「走神与做梦」 appears in Settings.

**Local directory install (source / development)**:

1. Put this directory anywhere (or keep the link);
2. Add it via the Plugins page, or `plugin_manager install_bundle` with the absolute directory path;
3. Confirm it is enabled in Settings → Plugins; refresh the page and 「走神与做梦」 appears in Settings;
4. Back up the profile's `package.json` and `cordis.patch.yml` before a local link install.

**Source development**: `git clone https://github.com/3297304308/dsh-dream-wander`, run `pnpm install` in the plugin directory, then link-install; changes hot-apply.

## Configuration

All fields and defaults (the panel is mostly dropdowns; paths, word lists and names are text inputs; saving hot-applies without YAML edits):

| Field | Default | Notes |
|---|---|---|
| `dreamEnabled` | `false` | dream switch (off by default) |
| `wanderEnabled` | `false` | wander switch (off by default) |
| `scope` | `[]` | session ids the plugin applies to (empty = inactive) |
| `wander.window` | `[8, 20]` | allowed hours (half-hour steps; wrap-around e.g. 22—6) |
| `wander.untilSleep` | `true` | extend the end of the window until the character falls asleep (no extra extension for wrap-around windows) |
| `wander.aloneMin` | `15` | minutes alone before the solo trigger |
| `wander.p` / `factor` / `threshold` / `max` | `0.3` / `2` / `10` / `50` | trigger chance / over-attention multiplier / threshold / max length |
| `wander.dupThreshold` | `0.95` | repetition threshold (0.1–1; similarity ≥ this counts as a repeat) |
| `cycle.residueP` | `0.3` | chance to bring a residue into a wander |
| `judge.confirmH` | `1` | hours of silence to confirm sleep (0–5, stepped) |
| `judge.windowH` | `6` | judging window (hours, 1–24) |
| `judge.dreamsPerDay` | `1` | dreams per day (Kmax) |
| `judge.hitP` | `0.5` | chance of a dream when sleeping through the whole window |
| `judge.lambdaRatio` / `lambdaHours` | `12` / `null` | Laplacian λ = window / ratio, or an explicit value |
| `play.halfChars` / `intervalMin` / `actsPerRelease` / `maxDurationMin` | `[100,200]` / `[10,30]` / `0.5` / `90` | half-act chars / release interval / acts per release / max dream minutes |
| `interrupt.sensitivity` | `mid` | weak / mid / strong (2 signals always break the dream) |
| `interrupt.weakPool` / `midPool` / `fullName` | one line each / `''` | drowsy line pools / full wake name |
| `interrupt.missP` / `startleP` | `0.05` / `0.02` | missed / startled chance |
| `actJump.sceneP` / `timeP` / `linkage` | `0.25` / `0.25` / `0.75` | act breaks: scene jump / time jump / linkage |
| `retry` | `2` | retries for failed generation/judging calls |
| `copy.degrade` | `daily` | copy degradation driver |
| `copy.visibility` | `[80,40,20,0,0]` | copy visibility sequence (retention is derived from it) |
| `frame.interruptMin` / `naturalMin` | `30` / `120` | how long the last frame stays (minutes) |
| `residue.form` | `blur` | `blur` = pixelated dream text (default in 0.1.0) / `words` = three words plus one sentence |
| `residue.hours` / `tiers` | `24` / `[50,100,200,300]` | words form only: retention hours and tier bounds |
| `residue.visibility` | `[50,30,10,0,0]` | blur form only: visible-ratio sequence |
| `mood.hours` | `2` | mood influence duration |
| `freq.stopwords` / `names` / `pronouns` | built-in / `[]` / five words | stopwords / name list / pronoun list |
| `bridge.dir` / `port` / `keys` | `''` / `3100` / `{}` | qq-bridge directory, port, session↔bridge-key map |
| `signal.pollIntervalSec` | `[2,5]` | signal polling interval (seconds) |
| `llm.provider` / `llm.model` | `deepseek-account` / `deepseek-flash` | generation channel |
| `dataDir` | `''` | data directory: empty = `<DSH_HOME>/dream-wander-data`; `./data` follows the plugin directory (recommended only for local/link installs) |

Deprecated fields (still parsed, ignored, hidden from the panel): `judge.kMin`, `judge.intervalMin`, `play.releaseMinutes`, `interrupt.count`, `actJump.chainP`, `copy.keepDays`, `mood.scale`.

## Data & privacy

- **What you will see**: wander paragraphs and dream copies live in files under the data directory (see below); the panel has a read-only **Contents** section where you can view today's wanders, the latest residue, the last 3 dream copies, the last frame and the in-progress dream text that has been released. The dream body **never appears in the chat**; the character only remembers the residue and the last frame.
- **Extra LLM calls**: one generation per wander; a dream is roughly one scene generation + one per half-act (about 10 with defaults; intervals/acts/retries change it). Injecting changed content rewrites the full system prompt once (long chats may see a token spike). All calls go through your configured LLM provider — no telemetry, no uploads.
- **Where the data lives**: `<DSH_HOME>/dream-wander-data` by default (`DSH_HOME` falls back to `~/.dsh`). Set `dataDir: "./data"` to keep data inside the plugin directory (portable); `DREAM_WANDER_DATA` env is also supported; relative paths resolve against the plugin directory.
- **Files**: `state.json` (state machine, judging progress, replacement bitmaps, word pool, session ids, **the character's wander texts and drowsy lines**), `走神/<date>.md`, `残留/`, `梦境副本/`, `plugin.log`, `apply-status.json`, `instance.lock`.
- **Contents viewer (read-only)**: the read-only section needs loopback source + loopback Host + same-origin + GET (POST 405, remote/foreign 403). Screenshot carefully — it shows dream/residue text (□ marks pixelated characters).
- **Before distributing**: delete `data/` and `instance.lock`; never commit them (git and npm packaging both exclude them).
- **Privacy note**: the plugin uploads nothing; but the data directory may be readable by the agent's own sandbox depending on your DSH setup.

## How remembering works

The character's knowledge is injected at prompt-assembly time from the current data directory — not hard-coded into chat messages. The full dream body exists only in memory and in the degraded copy files. The 6 injection blocks are split into two normalization strategies: volatile blocks (frame/mood/residue/dream-done/drowsy lines) are normalized as soon as they change; wander blocks are append-only with three fallbacks (3 pending appends, 4 hours since the last normalization, day rollover).

Signal channel (optional, qq-bridge):

- read-only polling of `GET /api/socialV2/unread` with the console token (no `x-agent-token`, does not raise the unread watermark)
- `agent/pre-step` intercepts input into the character's session during a dream (intercepted signals do not wake the character)
- passive replies/drowsy lines sent with the session token via `POST /api/send/private|group`
- bridge dive state (`wakeConfig.confirmedAt` with `confirmedBy=set_wake_config`) is one of the two wander sources

## Troubleshooting

| Symptom | Check first |
|---|---|
| No 「走神与做梦」 in Settings | plugin enabled? page refreshed? any load error in the Plugins page? |
| Switches on but nothing happens | scope selected? current time within the allowed window? Run Status says awake? |
| Never falls asleep / no dream | enough silence for `confirmH`? daily quota used up? word pool empty? hit chance is 0.5 by default |
| Panel returns 503 / plugin not started | `<data dir>/plugin.log` and `apply-status.json`; usually `instance.lock` held by another instance (use a different `dataDir` per profile) |
| Wander repeats itself | lower *dup threshold* (stricter) or raise it (looser) |
| Want to uninstall | see below; injected system prompts in old sessions are cleared after a turn or a session reset |

## Limitations

- Verified only against DSH 0.2.2-rc.3 (`engines.dsh` blocks incompatible versions but does not guarantee behavior)
- Panel UI is currently Chinese (`locale/` has English title/description only)
- Multiple sessions: only the first session in scope is used for signal polling
- Multiple profiles sharing the default data directory contend for `instance.lock` — give each profile its own `dataDir`
- A wander window whose start equals its end (e.g. 8–8) is invalid and never triggers
- The signal channel depends on qq-bridge's console token and state format
- This plugin does not modify the bridge, persona cards or the memory system

## Install / uninstall / turn off

- **Install**: see *Install*; fill `bridge.dir` and `bridge.keys` when qq-bridge is used.
- **Uninstall (prefer the plugin manager)**: remove `dsh-dream-wander` from the Plugins page; manually: ① remove `dependencies['dsh-dream-wander']` and the entry from `dsh.profile.bundles` in the profile's `package.json`, run `pnpm install` in the profile; ② remove the `id: dream-wander` override from the profile's `cordis.patch.yml`; ③ delete the plugin directory; ④ restart DSH. The data directory can be kept or deleted.
- **Turn off**: with both switches off the plugin is externally silent; background ticks still prune expired residue and degrade copies.
